# Graph contract

The semantic graph and its presentation serve different purposes. Machine-readable edge kinds live in `data.connectionType`: `network`, `volume`, `service-to-service`, and `depends_on`. Labels are readable presentation: network name, container mount path (volume name fallback), `communicates`, and `depends on`. Endpoint IDs and resource metadata remain independently testable.

Node builders preserve explicit dimensions and IDs. Standalone defaults are service 200×80, network 180×72, and volume 200×64. Labels identify services/volumes by the supplied node ID and networks by resource name (ID fallback). The map pipeline supplies its configured `nodeSize` as dimensions; layered placement reserves at least the visible BaseNode footprint of 200×80 as well as larger metadata dimensions. Arbitrarily expanding view content may still require runtime remeasurement/reflow; this is not a guarantee about unlimited rendered content.

The layered layout orders networks, services, then volumes, with up to two centered rows per category. `nodeLevelPadding` controls positive row/column gaps and the gap between annotation bands. Layer offsets use complete category bounds, including every row, and reserve annotation header/footer space. Bands use measured dimensions when available, metadata otherwise, and the minimum card footprint. Empty categories consume no rows. `platformPadding` sets the minimum node x/y in graph coordinates, matching the other engines' coordinate margins. ReactFlow `fitView` controls viewport whitespace separately; changing the graph-coordinate margin does not promise additional screen whitespace. Annotations derive their bounds from node positions, and boot-order positions are computed independently from AST dependencies, so they do not assume a centered layered origin. Selection uses IDs, unaffected by translation.

`EdgeBuilder.buildEdges` and `getAllEdges` include dependencies by default and honor an explicit `showDependencyEdges: false`. The map pipeline always retains dependency edges: the UI `showDependencies` setting highlights dependency relationships, and boot-order view needs them even when highlighting is off. View filtering belongs to DesignDeck and does not remove semantic dependency data during construction.

The two previously skipped MapMaker edge integration tests now execute against the real pipeline. They verify connections and IDs, sharing-network communication edges, unique IDs, and existing endpoints. Regression coverage checks padding relationships, small/large multirow node bounds and annotation bounds, explicit builder opt-out, and retained dependencies with both UI emphasis settings. Current raw resource IDs can still collide across resource kinds; UI-007 tracks that separate contract change.
