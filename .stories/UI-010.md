## User story and value

As a user, I need to distinguish configuration visualization from observed container health.

## Evidence and current behavior

`InspectorPanel.tsx` always shows a success badge labeled running for a service. `OutlinePanel.tsx` sets health to running on both branches of a healthcheck conditional. `BaseNode.tsx` always draws a green status dot. No live engine client is wired in the UI.

Paths above are repository-relative. This is a working-copy audit, not a claim about a deployed release. See core `AUDIT_EVIDENCE.md` for executed checks and limitations.

## Implementation scope

Use a shared runtime-state presentation with unknown/not-connected as the default. Preserve configured healthchecks as configuration information. Do not add an engine client in this correction.

## Acceptance criteria

- [x] Uploading a Compose file without engine data never displays running/healthy as an observed fact.
- [x] Inspector, outline and node indicators use consistent unknown/not-connected semantics.
- [x] Configured healthchecks are labeled as configuration, not execution evidence.
- [x] Future observed state has a source/time contract aligned with CORE-004, without blocking this fix.
